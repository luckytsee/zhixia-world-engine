# 01 · 世界引擎规格（World Engine SPEC v1）

> 对应设定稿：`（设定稿 Excel，未随本仓库发布）`（用户已验收冻结）
> 法典（人读）：`../world_rules.md`；机器参数（计算以此为准）：`../rules.json`
> 本文档回答：引擎**是什么、怎么跑、凭什么可信、别人怎么接**。

## 1. 定位

给知夏一个**少数几条底层规律不同、但长期稳定运行的世界**。引擎管事实（天气/时节/异象），
知夏管意义（怎么看待、今天出不门）。引擎不是 LLM，不生成一句自然语言。

三条根本规律：① 光潮周期（五阶不定长）② 雾影响感知（非空间）③ 季节与现实脱钩。
其余一切都是现象或异象。异象首发仅：静日（37 潮）、反向风、月出。

## 2. 四层架构

```
world_rules.md（法典，人读）＋ rules.json（参数，机器读）
        ↓
WorldEngine（纯函数状态机：光潮机 + 慢变量 + 异象掷骰）
        ↓ world_state.json（事实账本：当前状态 + 最近 30 潮历史）
render（渲染函数：状态 → 维度化字段，无台词）
        ↓
知夏的记忆块注入（她只见到现象）──→ 她的 world_notes（她对世界的理解，可以不精确，引擎不纠正）
```

- **她感知层不是一个存储**，就是 render 函数；她那份可能出错的认知唯一住处是她的 world_notes。
- 引擎读她的 world_notes 当气候参数（如「秋天总起雾」→ 雾阈补偿）——**v2 预留，v1 未接**。

## 3. 纯函数与冷启动（无常驻进程）

```
状态(现在) = advance(存档状态, 经过的时长)
```

- 知夏被查询/启动时，读 `world_state.json`，一次补算到此刻，写回存档。
- 电脑关一晚上，早上她的世界就是「走了一晚上」的状态——不冻结、不重置、一秒不白跑。
- 推进粒度：1 现实小时 = 1 步；绝对时桶 = `epoch秒 // 3600`，是一切时间噪声的种子键。

## 4. 确定性重放（本引擎的可信度所在）

| 随机量 | 种子键 |
|---|---|
| 阶段时长 | (dur, 潮序号, 阶段序号, 该阶段开始的绝对时桶) |
| 慢变量噪声 | (temp/hum/wind, 绝对时桶) |
| 异象（静日/月出/反向风） | (moon/rev/revh, 潮序号) |

- PRNG：mulberry32 + splitmix 风格键混合，全部 32 位整数运算；**字符串键按 UTF-8 字节
  小端折叠成 int**（`engine/rng.py::_key_int`，ArkTS 端必须同规则）。
- 保证：「逐步走 N 小时」≡「一次补算 N 小时」；存档 JSON 往返后重算 ≡ 不落盘直算。
  两者由 `tests/test_engine.py` 钉死。
- **验收向量卷**：`tests/test_vectors.json`（固定起点 + 6/30/400/2000 小时的完整状态与渲染文）。
  任何移植/重构，跑同一组输入必须同答案——这是手机端 ArkTS 实现的验收标准，不是口头承诺。

## 5. 模块与数据形态

```
世界引擎/
├── world_rules.md        法典（人读，含注入纪律）
├── rules.json            参数（计算唯一依据；快照下发时整份随行）
├── engine/
│   ├── rng.py            StepRng（确定性随机源，两端对答案的公共实现）
│   ├── engine.py         WorldEngine：initial_state / advance_to / month_of / year_of
│   └── render.py         render(state, engine) → {fields, block}
├── state/world_state.json  权威账本（只在电脑；首次运行由 initial_state 生成）
└── tests/                test_engine.py（9 项）+ make_vectors.py + test_vectors.json
```

state 关键字段：`engine_version / hour_abs / tide_index / phase / phase_remaining_h /
temp / humidity / wind / wind_reverse / fog / rain / static_day / moon_tonight /
last_moon_tide / reverse_until_h / history[≤30]`。

渲染输出（注入形态，全部是状态不是台词）：

```
【她那边此刻】
时节：沉静期·长暗月（第 1 年）
当前：入暗（这一段还剩约 4 小时）
光线：正在变暗，光快没了，太阳高度已落
林中状态：声音传得反常地远，方向感开始发飘
天气：潮气正常；微风
```

## 6. 手机端三原则（同事按此移植，PC 侧不做的部分）

1. **读模型补算**：手机本地实现 StepRng + advance（对向量卷验收），只用于离线时渲染
   「此刻」，一潮内小时级循环，开销可忽略。
2. **版本门**：快照带 `engine_version`；与本端实现版本不一致 → **不补算**，直接用快照里的
   状态（宁可世界停在出门时刻，也不能说出与电脑矛盾的话）。
3. **不回传**：权威账本只在电脑。手机补算结果是读模型，下次同步被快照整体覆盖，
   不回传、不合并、不参与仲裁。世界状态不是她生成的内容，天然不在仲裁管道里。

双开安全性：世界只依赖时间、不依赖聊天，两端各算各的必得同一结果。

## 7. 与主项目的接入点（下一步，不在本项目内）

- `desktop-ai-companion` 的 agent.py 在组装记忆块时调用 `render(state, engine)`，把 block
  拼进记忆段（几十字量级）。
- runtime 启动时 `advance_to(state, time.time())` 并落盘——世界随知夏醒来。
- 快照 `/sync/snapshot` 增加 `world` 段：`{engine_version, rules(整份), state, saved_at}`。
- 她的世界笔记暂不回灌引擎参数（v2）。

## 8. 红线（改代码前重读）

1. 禁用平台 random / 按调用次数播种——破坏确定性 = 破坏两端同世界。
2. 渲染层永远不出现数字（湿度 0.87 是内部账）与替她写好的口语。
3. 暗期她照常在：引擎不产出任何「她该下线」的语义。
4. rules.json 是计算唯一依据；world_rules.md 改了措辞必须同步参数，反之亦然。
5. 改任何会影响走向的代码 → 重跑 make_vectors 并人工过目新旧差异（世界改版要留痕）。
