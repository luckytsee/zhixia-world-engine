# 06 · 扩展方向：真的接上去（工具与起停）

> 前三篇讲"怎么设计"，这一篇讲"**用什么接、怎么起、怎么停**"。
> 只讲我们实际用过的那条路和踩过的坑，不给实现代码——它涉及你的真实账号。

---

## 一、用什么接

| 项 | 我们的选择 | 说明 |
|---|---|---|
| 后台操作工具 | **wxauto4**（免费版） | 基于 Windows UI 自动化（UIA）操作微信窗口，**不需要 hook、不注入** |
| 微信 | **桌面版**（装在你自己的电脑上） | 它操作的是**你已经登录的那个客户端**，不是网页版协议 |
| 平台 | **Windows** | 这套方案依赖 UIA，只在 Windows 上成立 |

**它是怎么工作的**：程序通过 UIA 读微信窗口里的消息列表、模拟鼠标点进某个会话、调用发送。
——也就是说，**微信就是一个普通的桌面程序，程序替你去点它**。

⚠️ **先想清楚这件事的代价**：它要求**微信一直在那台电脑上开着、保持登录**。关掉微信、
退出登录、电脑睡眠，她就下线了。这是这条路线的固有属性，不是 bug。

---

## 二、免费版的限制：不能"等回调"，只能"自己轮询"

wxauto 的**回调监听是付费版功能**。免费版要自己搭轮询：

```
读会话列表（纯 UIA，零鼠标）
  → 发现白名单里的人有新消息
    → 点进那个会话，读新内容
      → 攒批、回消息
```

⚠️ **关键设计：平时只读会话列表，不点进去。**

因为"点进某个会话"（`ChatWith`）是**真实的鼠标模拟**——如果每几秒点一次，
**你会没法用鼠标**（程序在跟你抢）。所以只在白名单的人真有新消息时才点进去读一次。

**这条是必须做的**，否则这个方案在你日常用电脑时完全不可用。

## 三、起停顺序：都可以，但有几件事要知道

### 3.1 谁先谁后都行——但要能自愈

**先开知夏、后开微信**是可以的：连不上就重试，微信起来了自动接上。
**先开微信**更顺，但没必要强求。

⚠️ **必须实现断线自愈**，否则会遇到这个：

> 微信退出登录后，程序手里的窗口引用**全部失效**——表现为不停地报"找不到控件"，
> **而且永远不会自己恢复**。

正确做法：**连续 N 次轮询失败就判定掉线** → 丢弃旧引用 → 退避重连 → 连上后重新建立基线。
**离线期间的消息一律不回复**（否则她会在你重新登录后，把几小时前的消息一条条回一遍）。

### 3.2 重连后要有静默期

微信重新登录后会**延迟同步**离线期间的消息。如果基线拍得太早，
那些消息会在之后的轮询里冒出来，被当成新消息。

做法：**重连成功后先静默一段时间**（我们用的是 30 秒），期间冒出来的全部当已读吸收掉。
不这样做，她会在你登录后突然回复一堆过期消息。

### 3.3 中途想关掉微信

- **关微信**：程序检测到掉线，进入重试循环（不会崩，但也不工作）；
- **想彻底停下她**：把配置里的通道开关关掉（**不用改代码**），比关微信干净；
- **想临时静音**：白名单清空 = 谁都不回。

**建议**：给这一层配一个**独立开关**，而不是靠"开不开微信"来控制——
否则你半夜想安静，就得退出微信。

## 四、三个只有真跑过才知道的坑

### 4.1 别去动微信窗口的显示状态

我们曾加过一个"把微信从最大化还原成小窗"的功能——**结果 UIA 读不全，监听线程崩溃，
把 A 的消息读成了 B 的**。

**结论：不要动用户 IM 窗口的显示状态。** 用户自己的用法就是最优的。

### 4.2 消息 ID 不能当"已读"的依据

实测：**同一条消息会以多个不同的 ID 反复出现**（90 条里 42 条如此）。
按 ID 记"读过没有"必然失效——表现是重复回复、重复登记。

做法：**已读账本用"内容指纹 + 顺序对齐"**，并且要带上下文校验，
才能同时保住两件事：**读过的不要重复回、重发的要能回**。

### 4.3 双开是真实风险（账号锁）

**双开微信时，wxauto 认主窗口只靠窗口类名，取枚举到的第一个**——
**连错了不会报错**。万一连到你的私人号，而白名单里的名字恰好也是你的好友，
**可能直接发给真人**。

做法：**加账号锁**——连上之后先读"当前登录的是谁"，跟配置里写死的那个账号比对，
**不一致就拒绝操作**。这是硬性要求，不是可选优化。

## 五、发送这件事本身也有讲究

- **发送会弹独立窗口并抢前台**——所以发送前要等系统输入空闲（忙时就延迟发），
  减少对你正在做的事的打断；
- **发送前必须清洗**：内部的情绪标签、`[记住:]` 标记要在代码里剥掉再发；
- **失败要响**：发送失败必须报出来。静默失败会让你以为她在正常聊天，其实一条没发出去。

## 六、怎么"被拉起来"：开机自启与绑定

接 IM 之后，你多半希望**开机就自动在跑**，而不是每次手动双击。三种形态：

| 方式 | 做法 | 适合 |
|---|---|---|
| **手动** | 双击一个启动脚本 | 调试期（推荐先这样） |
| **开机自启** | 放进系统的启动项（启动文件夹 / 计划任务） | 日常使用 |
| **服务化** | 注册成系统服务，开机自启、崩溃自动重启 | 想让它长期无人值守时 |

⚠️ **三条实务提醒**：

1. **自启要能"等微信"**——开机时微信可能比你的程序起得晚。所以连不上要**重试**，
   而不是启动失败就退出（这也是前面说"先开谁都行"能成立的前提）；
2. **要能一键停**——放在启动项里的东西，最怕"想关关不掉"。**配一个停止脚本或托盘菜单**，
   不用去任务管理器里找进程；
3. **崩溃重启要限次数**——无限重启会在出问题时刷满日志、甚至触发风控。
   常见做法是"退回退避"，重启间隔逐次拉长。

**绑定关系一句话**：程序**绑定的是"那个已登录的微信窗口"**，不是账号协议。
所以：**微信开着 = 她在；微信关了 = 她下线**。这也是为什么前面反复说
"别靠开关微信来控制她"——那是两件事，要分开。

## 七、最小可用清单

想跑通，至少要有：

1. Windows + 桌面微信 + wxauto4；
2. **白名单**（只处理列出的单聊，群聊一律不碰）；
3. **账号锁**（连错账号直接停）；
4. **轮询 + 会话驱动**（平时只读列表，不抢鼠标）；
5. **断线自愈 + 重连静默期**；
6. **已读账本用内容指纹**（不是消息 ID）；
7. **一个独立开关**（不用靠开关微信来控制）。

## 附：为什么没有更具体的步骤

因为具体的窗口类名、控件路径、微信版本差异，**会随微信更新而变**——
写死在文档里，过两个月就是错的。这里只给**结构、顺序和坑**，
剩下的在你的环境里跑一遍就能摸出来。

⚠️ 最后一句：**这套东西操作的是你的真实账号**。先用只读模式（只记日志不发）跑一阵，
再决定要不要放开发送。
