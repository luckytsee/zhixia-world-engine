# 05 · 扩展方向：让她说话（思路）

> 这一篇只讲一件事：**情绪怎么变成语气**。
> 不讲训练、不讲部署细节——仓库主体也不含任何语音实现（涉及人声音色素材）。

---

## 一、三条路，一条推荐

| 路线 | 一句话 |
|---|---|
| 本地 TTS 微调 | 离线、免费、音色属于自己；**但效果与云端差一个量级**（架构差异，调参补不回来） |
| **GPT 系推理** | **能用不同参考音频控制语气**——唯一能做到"带情绪说话"的一条 |
| **云端克隆** | **实测效果最好**（我们试过的方案里，它复刻出的音色连呼吸声都在） |

**推荐起步用云端克隆**：先把"她说话"这件事跑通、听感过关，再考虑离线与成本。
本地那条路留作"想省钱/想完全离线"时的备选。

---

## 二、情绪 → 句子 → 语气（这一篇的重点）

**能不能让同一句话听起来不一样，决定了语音是加分还是减分。**

一段情绪标签（`[happy]` / `[sad]` / `[tired]`…）本身**不能直接送给语音引擎**——
它不认识"happy"这个标签，它只认识**你给它听的那段参考音频听起来怎么样**。

所以链路上真正起作用的是中间这一层：

```
情绪（她这一轮的心情）
   ↓ 决定
语气（这句话该怎么说：轻快 / 低落 / 撒娇 / 疲惫 / 认真）
   ↓ 选择
参考音频（该语气对应的素材）
   ↓ 合成
这句话的语音
```

**关键结论**：要想让她"看心情说话"，要做的不是调参数，而是
**给每种情绪准备几条对应的参考音频，按标签挑一条去合成。**

### 2.1 每种情绪配一条"参考句"

参考句的要点：**5–15 秒、一句话、内容中性**（别录带强烈语义的句子，
比如"我好开心啊"配低落的语气——**语义会干扰语气判断**）。

| 情绪标签 | 语气 | 参考句的样子（示例，自己录/剪） |
|---|---|---|
| `[happy]` | 轻快、尾音上扬 | "今天天气不错啊，出去走走？" |
| `[sad]` | 低落、语速慢、气息弱 | "……算了吧，不想说了。" |
| `[angry]` | 短促、重音靠前（**别真吼**） | "你怎么又这样。" |
| `[tired]` | 拖沓、气声多、尾音沉 | "让我先歇会儿……有点累。" |
| `[curious]` | 疑问上扬、语速偏快 | "咦，这个是怎么回事？" |
| `[surprised]` | 起音高、节奏断 | "啊？真的假的。" |
| `[neutral]` | 平铺直叙 | "嗯，知道了。" |

⚠️ **两条实操要点**：

1. **每种准备 2–3 条**，合成时随机挑一条——同一条反复用，同一情绪会听起来像复读机；
2. **素材必须同一个人、同一种录音环境**——音色一致性全靠这个，混用会串味。

### 2.2 顺序不能反

**先定"她怎么说话"，再定"用什么合成"。**

如果不管内容是什么，语音永远是同一个语调——**再好的音色也会显得假**。
所以顺序应该是：

1. 先让人格产出**准确的语气标签**（`agent.py` 已经在做：从回复里解析情绪）；
2. 再让语音按标签挑参考音频；
3. **最后**才追求音色相似度。

反过来做（先追求音色、语气不管）——**你会得到一把好嗓子在念稿子**。

---

## 三、一条底线

**语音必须是可选的。** 服务没开、网络断了、额度用完——**她都要能正常用文字聊**。

做法：把合成包在"可用性检查 + 失败静默降级"的壳里，上层只看到"这条消息有没有语音"，
**合成失败就当纯文字消息发出去**。语音是加分项，不能成为单点故障。

---

## 附：这一层为什么没进仓库

语音涉及**人声音色素材**（可能来自真人）、API 凭据、以及各家的商业条款，
这些都不适合随代码分发。所以这里只给链路和取舍。
